☕ update-javaエイリアスの詳細

エイリアスコマンド

update-java

☕ Javaとは

Javaは、Webアプリ・Androidアプリ・業務システムなど幅広い用途で使われるプログラミング言語および実行環境です。Javaで作られたプログラムを動かすには「JDK（Java Development Kit）」のインストールが必要です。

🔒 なぜアップデートが必要か

  • セキュリティ: 古いバージョンには脆弱性が存在することがあり、定期的な更新で安全性を保てます
  • 互換性: 新しいライブラリやフレームワークは最新のJavaバージョンを要求することがあります
  • パフォーマンス: 新バージョンでは実行速度や省メモリが改善されています

🔍 コマンドの動作説明

Apple Silicon（M1/M2）とIntel Macを自動判定し、適切なJavaをインストール・更新するコマンドです。

💡 使用方法

  1. ターミナルでupdate-javaコマンドを実行
  2. システムのアーキテクチャが自動判定される
  3. 該当するJavaをインストール・更新

⚙️ 特徴

  • Apple Silicon (ARM64)とIntel (x86_64)を自動判定
  • 各アーキテクチャに最適なJavaをインストール
  • 既にインストール済みの場合は更新を実行

📋 元のコード

update-java() {
  if [ -d "/opt/homebrew/opt/openjdk" ]; then
    echo "Apple Silicon Macとして実行"
    brew install openjdk && sudo ln -sfn /opt/homebrew/opt/openjdk/libexec/openjdk.jdk /Library/Java/JavaVirtualMachines/openjdk.jdk && echo "export PATH=\"/opt/homebrew/opt/openjdk/bin:\$PATH\"" >> ~/.zshrc && source ~/.zshrc && java -version
  else
    echo "Intel Macとして実行"
    brew install openjdk && sudo ln -sfn /usr/local/opt/openjdk/libexec/openjdk.jdk /Library/Java/JavaVirtualMachines/openjdk.jdk && echo "export PATH=\"/usr/local/opt/openjdk/bin:\$PATH\"" >> ~/.zshrc && source ~/.zshrc && java -version
  fi
}

🖼️ herowebpエイリアスの詳細

エイリアスコマンド

herowebp

🔍 コマンドの動作説明

jpg/jpeg/png/heic形式の画像を3つのサイズのWebP形式に自動変換します。ヒーロー画像などレスポンシブで複数サイズが必要な場合に便利です。

💡 使用方法

  1. カレントディレクトリの画像を配置
  2. ターミナルでherowebpコマンドを実行
  3. 以下の3サイズのWebP画像が自動生成されます：
    • 1920x1080px
    • 1200x675px
    • 800x450px

⚙️ 対応形式

  • 入力形式: jpg, jpeg, png, heic
  • 出力形式: WebP (複数サイズ)

📋 元のコード

herowebp() {
  local quality=50
  local method=6
  for img in *.{jpg,jpeg,png,heic}; do
    if [ -f "$img" ]; then
      base="${img%.*}"
      echo "Processing: $img"
      magick "$img" -resize 1920x1080 -quality $quality -define webp:method=$method "${base}_1920x1080.webp"
      magick "$img" -resize 1200x675 -quality $quality -define webp:method=$method "${base}_1200x675.webp"
      magick "$img" -resize 800x450 -quality $quality -define webp:method=$method "${base}_800x450.webp"
      echo "✓ Generated WebP files for: $img"
    fi
  done
}

🖼️ webp50エイリアスの詳細

エイリアスコマンド

webp50

🔍 コマンドの動作説明

jpg/jpeg/png/heic形式を自動検出して、高圧縮率のWebPに変換します。品質50とmethod=6（最高品質の圧縮）で最適なバランスを実現します。

💡 使用方法

  1. カレントディレクトリの画像を配置
  2. ターミナルでwebp50コマンドを実行
  3. 同じフォルダにWebP形式の画像が生成されます

⚙️ 圧縮オプション

  • quality=50: 品質レベル (0-100、50は標準的な圧縮)
  • method=6: 圧縮方法 (0-6、6は最高品質)

📋 元のコード

webp50() {
  local quality=50
  local method=6
  local count=0
  for file in *.{jpg,jpeg,png,heic}; do
    if [ -f "$file" ]; then
      local base="${file%.*}"
      if [ -f "${base}.webp" ]; then
        echo "⊘ Already exists: ${base}.webp (skipped)"
        continue
      fi
      echo "Converting: $file → ${base}.webp"
      magick "$file" -quality $quality -define webp:method=$method "${base}.webp"
      if [ $? -eq 0 ]; then
        echo "✓ Converted: $file"
        ((count++))
      else
        echo "✗ Failed to convert: $file"
      fi
    fi
  done
  echo ""
  if [ $count -gt 0 ]; then
    echo "✓ Successfully converted $count file(s) to WebP"
  else
    echo "⊘ No new files to convert"
  fi
}

🖼️ img2jpegエイリアスの詳細

エイリアスコマンド

img2jpeg

🔍 コマンドの動作説明

複数の画像形式をJPEGに統一して変換します。長辺を1080pxにリサイズするため、ウェブ用途に最適なサイズになります。

💡 使用方法

  1. カレントディレクトリの画像を配置
  2. ターミナルでimg2jpegコマンドを実行
  3. 同じフォルダにJPEG形式（長辺1080px）の画像が生成されます

⚙️ 変換設定

  • 出力形式: JPEG
  • 最大長辺: 1080px
  • アスペクト比: 維持

📋 元のコード

img2jpeg() {
  setopt nullglob
  local count=0
  local failed=0
  local total=0

  for file in *.tiff *.tif *.png *.jpeg *.jpg *.heic; do
    [ -f "$file" ] || continue
    local base="${file%.*}"
    ((total++))

    echo "Converting: $file → ${base}.jpg"
    sips -s format jpeg -Z 1080 "$file" --out "${base}.jpg" &>/dev/null

    if [ $? -eq 0 ]; then
      echo "✓ $(basename "$file")"
      ((count++))
    else
      echo "✗ $(basename "$file")"
      ((failed++))
    fi
  done

  echo ""
  if [ $total -eq 0 ]; then
    echo "⊘ No image files found (tiff, tif, png, jpeg, jpg, heic)"
  elif [ $count -gt 0 ]; then
    echo "✓ Successfully converted $count file(s) to JPEG"
  fi
  if [ $failed -gt 0 ]; then
    echo "✗ Failed to convert $failed file(s)"
  fi
}

🖼️ avifエイリアスの詳細

エイリアスコマンド

avif

🔍 コマンドの動作説明

カレントディレクトリ以下を再帰的に検索し、HEIC/HEIF/JPG/JPEG/PNG/TIFF/TIF/BMP/GIF 形式の画像を AVIF 形式に一括変換します。sips で一時 PNG に変換後、avifenc で品質60の AVIF を生成。変換成功後は元ファイルと一時 PNG を削除します。既に同名の .avif が存在する場合はスキップします。

💡 使用方法

  1. 変換したい画像が含まれるフォルダへ移動
  2. ターミナルでavifを実行
  3. サブフォルダを含む全画像が AVIF 形式に変換されます

⚙️ 変換設定

  • 入力形式: HEIC, HEIF, JPG, JPEG, PNG, TIFF, TIF, BMP, GIF
  • 出力形式: AVIF（品質60）
  • 既存の .avif はスキップ
  • 変換成功後に元ファイル・一時 PNG を自動削除
  • 必要ツール: sips（macOS 標準）、avifenc（要インストール）

📋 元のコード

find . -iname "*.heic" -o -iname "*.heif" -o -iname "*.jpg" -o -iname "*.jpeg" -o -iname "*.png" -o -iname "*.tiff" -o -iname "*.tif" -o -iname "*.bmp" -o -iname "*.gif" | while read f; do
  tmp="${f%.*}_tmp.png"
  out="${f%.*}.avif"
  [[ -f "$out" ]] && continue
  sips -s format png "$f" --out "$tmp" && \
  avifenc -q 60 "$tmp" "$out" && \
  rm "$tmp" "$f"
done

✂️ trim95関数の詳細

コマンド

trim95

🔍 コマンドの動作説明

カレントディレクトリの .heic ファイルを中央から95%サイズにクロップします。macOS 標準の sips を使用するため、ImageMagick 不要。元ファイルはそのまま残し、trimmed_ プレフィックスを付けて出力します。

💡 使用方法

  1. クロップしたい HEIC 画像が含まれるフォルダへ移動
  2. ターミナルで trim95 を実行
  3. 各ファイルの trimmed_元ファイル名.heic が生成されます

⚙️ 処理内容

  • 入力形式: HEIC
  • クロップ率: 縦横それぞれ 95%（中央基準）
  • 出力: trimmed_元ファイル名.heic（元ファイルは保持）
  • 必要ツール: sips（macOS 標準搭載、追加インストール不要）

📋 関数の設定（初回のみ）

🔧 ~/.zshrc への追加

以下のコマンドを実行すると関数が登録されます:

cat >> ~/.zshrc << 'EOF'
trim95() {
  for file in *.heic; do
    [ -f "$file" ] || continue
    read w h < <(sips -g pixelWidth -g pixelHeight "$file" | awk '/pixelWidth/{w=$2} /pixelHeight/{h=$2} END{print w, h}')
    crop_w=$(echo "scale=0; $w * 95 / 100" | bc)
    crop_h=$(echo "scale=0; $h * 95 / 100" | bc)
    offset_x=$(( (w - crop_w) / 2 ))
    offset_y=$(( (h - crop_h) / 2 ))
    sips --cropToHeightWidth $crop_h $crop_w --cropOffset $offset_y $offset_x "$file" --out "trimmed_${file}"
  done
}
EOF
source ~/.zshrc

🖨️ h2pエイリアスの詳細

エイリアスコマンド

h2p

🔍 機能説明

HEIC形式の画像をJPG形式に変換してから、SHARPカラープリンタで自動的にカラー印刷します。画像の向き（縦横）を自動判定し、用紙に最適な方向で印刷します。

💡 使用方法

基本的な使用手順：

  1. 印刷したい HEIC ファイルがあるフォルダでターミナルを開く（またはカレントディレクトリに HEIC ファイルを配置）
  2. 必要に応じて hrsz() で画像をトリム・リサイズ（2480x3508 または 3508x2480）
  3. ターミナルで h2p を実行

🔄 処理フロー

  • HEIC → JPG 変換：ImageMagick (magick) を使用して自動回転対応で変換
  • 画像サイズ判定：変換後のJPGサイズから向きを自動判定
    • 横長（幅 > 高さ）→ 横向き印刷
    • 縦長（幅 ≤ 高さ）→ 縦向き印刷
  • 用紙いっぱい印刷：fit-to-page オプションで拡大印刷
  • カラー印刷：ColorModel=RGB を指定
  • 自動クリーンアップ：印刷完了後、一時JPGファイルを削除

📋 エイリアス定義

h2p() {
  setopt nullglob
  for file in ./*.heic; do
    [ -f "$file" ] || continue
    jpg="${file%.heic}.jpg"
    if ! magick "$file" -auto-orient "$jpg"; then
      echo "✗ エラー: $(basename "$file") の変換に失敗"
      rm -f "$jpg"
      continue
    fi
    dimensions=$(magick identify -format "%w %h" "$jpg")
    width=$(echo $dimensions | cut -d' ' -f1)
    height=$(echo $dimensions | cut -d' ' -f2)
    if [ "$width" -gt "$height" ]; then
      orientation=4
    else
      orientation=3
    fi
    if lp -d SHARP_BP_60C26__3504320300_ -o ColorModel=RGB -o fit-to-page -o orientation-requested=$orientation "$jpg" &>/dev/null; then
      sleep 3
      rm -f "$jpg"
      echo "✓ 処理完了: $(basename "$file")"
    else
      echo "✗ エラー: $(basename "$file") の印刷に失敗"
      rm -f "$jpg"
    fi
  done
}

🖼️ hrszエイリアスの詳細

エイリアスコマンド

hrsz

🔍 機能説明

HEIC形式の画像を正規化サイズにリサイズ・トリムします。画像の向き（縦横）を自動判定し、アスペクト比を損なわないように中央からトリムして、3508x2480 または 2480x3508 のサイズに統一します。

💡 使用方法

基本的な使用手順：

  1. HEIC ファイルがあるフォルダで hrsz を実行
  2. 画像の向きに応じて自動的にサイズを決定
  3. output/ フォルダに処理済み画像を出力

🔄 処理フロー

  • サイズ判定：元画像の幅と高さを取得
    • 横長（幅 > 高さ）→ 3508x2480 にリサイズ・トリム
    • 縦長（幅 ≤ 高さ）→ 2480x3508 にリサイズ・トリム
  • 高品質リサイズ：-density 300 で 300 DPI に設定
  • 中央トリム：-gravity Center で中央からトリム（アスペクト比を損なわない）
  • 拡大対応：-resize ^ で小さい画像も拡大可能
  • ファイル保持：元のファイル名で output/ に出力

📋 エイリアス定義

hrsz() {
  output_dir="output"
  mkdir -p "$output_dir"
  for file in *.heic; do
    width=$(magick identify -format "%w" "$file")
    height=$(magick identify -format "%h" "$file")
    if [ "$width" -gt "$height" ]; then
      magick "$file" -density 300 -gravity Center -resize 3508x2480^ -crop 3508x2480+0+0 +repage "$output_dir/$file"
    else
      magick "$file" -density 300 -gravity Center -resize 2480x3508^ -crop 2480x3508+0+0 +repage "$output_dir/$file"
    fi
    echo "✓ 処理完了: $file"
  done
  echo "✅ 全ファイルが $output_dir フォルダに出力されました"
}

hrsz500() {
  mkdir -p ~/Desktop/original_images
  mkdir -p output

  find . -type f \( -iname "*.jpeg" -o -iname "*.jpg" -o -iname "*.png" \) | while read file; do
    filename=$(basename "$file" | sed 's/\.[^.]*$//')
    output_file="output/${filename}.heic"
    magick "$file" -resize 500x500 -gravity center -background white -extent 500x500 -density 72 -quality 75 "$output_file"
    mv "$file" ~/Desktop/original_images/
    echo "Converted & resized: $(basename "$file") → $(basename "$output_file") (original moved)"
  done

  find . -type f -iname "*.heic" | while read file; do
    filename=$(basename "$file")
    temp_file="output/${filename}.tmp"
    magick "$file" -resize 500x500 -gravity center -background white -extent 500x500 -density 72 -quality 75 "$temp_file"
    mv "$temp_file" "output/${filename}"
    echo "Resized: output/$(basename "$file")"
  done
}

🔢 rnエイリアスの詳細

エイリアスコマンド

rn

🔍 コマンドの動作説明

カレントディレクトリにある画像ファイル（jpg/jpeg/png/tiff/tif/gif/webp/bmp）を対話形式で連番リネームします。開始番号・前後に付ける文字列を指定でき、実行前にプレビューで確認できます。

💡 使用方法

  1. リネームしたい画像があるフォルダに移動
  2. ターミナルでrnを実行
  3. 開始番号を入力して確認
  4. 番号の前後に文字列を追加するか選択（任意）
  5. プレビューを確認してリネーム実行

⚙️ 主な機能

  • 対応形式：jpg / jpeg / png / tiff / tif / gif / webp / bmp
  • 開始番号の入力バリデーション（数字以外はエラー）
  • 番号の前（prefix）または後（suffix）に任意文字列を追加可能
  • リネーム前にプレビュー表示・確認プロンプト
  • mv -iで既存ファイルへの上書きを防止

📋 元のコード

rn() {
  # 開始番号を訊く
  while true; do
    echo -n "開始番号を入力してください: "
    read start
    if [[ -z "$start" || ! "$start" =~ ^[0-9]+$ ]]; then
      echo "エラー: 数字を入力してください。"
      continue
    fi
    echo -n "開始番号は「${start}」でよいですか？ (y/n): "
    read confirm_start
    [[ "$confirm_start" == "y" ]] && break
  done

  # 前後に文字列を付けるか訊く
  local prefix=""
  local suffix=""
  echo -n "番号の前後に文字列を追加しますか？ (y/n): "
  read add_str
  if [[ "$add_str" == "y" ]]; then
    echo -n "文字列を入力してください: "
    read str
    echo -n "番号の「前」ですか「後」ですか？ (前/後): "
    read pos
    if [[ "$pos" == "前" ]]; then
      prefix="$str"
    else
      suffix="$str"
    fi
  fi

  # 対象ファイルを画像から自動検出
  local img_files=()
  for f in *(N-.); do
    [[ "$f" =~ \.(jpg|jpeg|png|tiff|tif|gif|webp|bmp)$ ]] && img_files+=("$f")
  done

  if [[ ${#img_files[@]} -eq 0 ]]; then
    echo "対象の画像ファイルが見つかりません。" >&2
    return 1
  fi

  # プレビュー表示
  echo ""
  echo "【プレビュー】"
  local n=$start
  for f in "${img_files[@]}"; do
    local ext="${f##*.}"
    local new_name="${prefix}${n}${suffix}.${ext}"
    echo "$f → $new_name"
    (( n++ ))
  done

  # 確認
  echo ""
  echo -n "このままリネームしますか？ (y/n): "
  read confirm
  if [[ "$confirm" != "y" ]]; then
    echo "キャンセルしました。"
    return 0
  fi

  # 実行
  n=$start
  for f in "${img_files[@]}"; do
    local ext="${f##*.}"
    local new_name="${prefix}${n}${suffix}.${ext}"
    mv -i -- "$f" "$new_name"
    (( n++ ))
  done
  echo "リネーム完了しました。"
}

エイリアスコマンド

zp

🔍 コマンドの動作説明

カレントディレクトリ自体を1つのZIPファイルにまとめます。ZIPファイルは親ディレクトリに作成されます。

💡 使用方法

  1. ZIP化したいディレクトリに移動（cd コマンドで対象ディレクトリへ）
  2. ターミナルでzpコマンドを実行
  3. カレントディレクトリと同名のZIPファイルが親ディレクトリに作成されます

⚙️ 処理内容

  • 処理対象: カレントディレクトリ全体
  • エンコーディング: CP932（Windows互換）
  • 出力先: 親ディレクトリ（カレントディレクトリ名.zip）
  • 既にZIPが存在する場合はスキップ

📋 元のコード

zp() {
  local dirname=$(basename "$PWD")
  local zipname="${dirname}.zip"
  local zip_path="$(dirname "$PWD")/$zipname"

  # 既にZIPが存在する場合はスキップ
  if [ -f "$zip_path" ]; then
    echo "⊘ スキップ: $dirname (既にZIPが存在します: $zip_path)"
    return 1
  fi

  echo "処理中: $dirname → $zip_path"

  # ZIPフォーマットをバイナリで直接書き出す（UTF-8フラグ強制セットを回避）
  python3 << PYTHON_EOF
import os, sys, struct, zlib, time

try:
    folder_path = "$PWD"
    zip_path = "$zip_path"
    parent_path = os.path.dirname(folder_path)

    entries = []

    with open(zip_path, 'wb') as zf:
        for root, dirs, files in os.walk(folder_path):
            dirs.sort()
            for file in sorted(files):
                file_path = os.path.join(root, file)
                arcname = os.path.relpath(file_path, parent_path)
                arcname_bytes = arcname.encode('cp932')

                with open(file_path, 'rb') as f:
                    data = f.read()

                compressed = zlib.compress(data, 6)[2:-4]  # deflate
                crc = zlib.crc32(data) & 0xFFFFFFFF
                t = time.localtime()
                dostime = (t.tm_hour << 11) | (t.tm_min << 5) | (t.tm_sec // 2)
                dosdate = ((t.tm_year - 1980) << 9) | (t.tm_mon << 5) | t.tm_mday

                offset = zf.tell()

                # Local file header
                lh = struct.pack('<4sHHHHHIIIHH',
                    b'PK\x03\x04',
                    20,          # version needed
                    0,           # flags: 0 (no UTF-8 flag)
                    8,           # compression: deflate
                    dostime, dosdate,
                    crc,
                    len(compressed),
                    len(data),
                    len(arcname_bytes),
                    0            # extra field length
                )
                zf.write(lh)
                zf.write(arcname_bytes)
                zf.write(compressed)

                entries.append((arcname_bytes, crc, len(compressed), len(data), dostime, dosdate, offset))

        # Central directory
        cd_offset = zf.tell()
        for arcname_bytes, crc, comp_size, uncomp_size, dostime, dosdate, offset in entries:
            cd = struct.pack('<4sHHHHHHIIIHHHHHII',
                b'PK\x01\x02',
                20,          # version made by
                20,          # version needed
                0,           # flags: 0
                8,           # compression
                dostime, dosdate,
                crc,
                comp_size,
                uncomp_size,
                len(arcname_bytes),
                0, 0, 0, 0,  # extra, comment, disk, attr
                0,           # external attr
                offset
            )
            zf.write(cd)
            zf.write(arcname_bytes)

        # End of central directory
        cd_size = zf.tell() - cd_offset
        eocd = struct.pack('<4sHHHHIIH',
            b'PK\x05\x06',
            0, 0,
            len(entries), len(entries),
            cd_size, cd_offset,
            0
        )
        zf.write(eocd)

    sys.exit(0)
except Exception as e:
    print(f"✗ エラー: {e}")
    sys.exit(1)
PYTHON_EOF

  if [ $? -eq 0 ]; then
    echo "✓ 完了: $zip_path"
  else
    echo "✗ エラー: $dirname の変換に失敗しました"
  fi
}

📋 関数の設定（初回のみ）

🔧 ~/.zshrc への追加

以下のコマンドを実行すると関数が登録されます:

cat >> ~/.zshrc << 'EOF'
p2ha4() {
  local pct=${1:-100}
  for pdf in *.pdf; do
    [ -f "$pdf" ] || continue
    base="${pdf%.*}"
    magick -density 300 "$pdf" -quality 100 "__p2h_${base}_%04d.png"
    for png in "__p2h_${base}"_*.png; do
      [ -f "$png" ] || continue
      stem="${png#__p2h_}"; stem="${stem%.png}"
      tmp_heic="__p2h_${stem}.heic"
      out_heic="${stem}.heic"
      heif-enc "$png" -o "$tmp_heic" && rm "$png"
      read w h < <(sips -g pixelWidth -g pixelHeight "$tmp_heic" | awk '/pixelWidth/{w=$2} /pixelHeight/{h=$2} END{print w, h}')
      max_w=$(( w * pct / 100 ))
      max_h=$(( h * pct / 100 ))
      if (( max_w * 297 >= max_h * 210 )); then
        crop_h=$max_h
        crop_w=$(echo "scale=0; $max_h * 210 / 297" | bc)
      else
        crop_w=$max_w
        crop_h=$(echo "scale=0; $max_w * 297 / 210" | bc)
      fi
      offset_x=$(( (w - crop_w) / 2 ))
      offset_y=$(( (h - crop_h) / 2 ))
      sips --cropToHeightWidth $crop_h $crop_w --cropOffset $offset_y $offset_x "$tmp_heic" --out "$out_heic" && rm "$tmp_heic"
    done
  done
}
EOF

🔍 コマンドの動作説明

  • 変換方法: -c copyオプションでコンテナだけを変更し、ビデオ・オーディオの再エンコードを行わない

  4. 同じフォルダにmp4ファイルが生成されます

⚙️ 処理内容

  • 対象: カレントディレクトリ内のすべてのm4vファイル

🖼️ dskw関数の詳細

実行コマンド

dskw

🔍 コマンドの動作説明

PDFをHEICに変換してCanvaに取り込む運用の中で、罫線のある表形式の書類画像（自動車検査証記録事項など）に2種類の歪みが生じることが判明しました。

  • 回転ずれ: 罫線全体がわずかに右下がり／右上がりになる
  • せん断ずれ: 垂直の罫線が左右で同じ角度だけ傾き、平行四辺形状になる

単純な回転補正だけでは後者が残るため、回転＋せん断の2段階補正を行います。引数は取らず、カレントフォルダ内の対象画像を一括処理します。

💡 使用方法

  1. 補正したい画像が入ったフォルダへ移動
  2. ターミナルでdskwを実行
  3. 各ファイルの 元ファイル名_corrected.拡張子 が生成されます
  4. 実行中、検出角度・検出画素数・補正後の残存角度が表示されます

⚙️ 処理内容

  • 対応拡張子: heic / png / jpg / jpeg（nocaseglob により大文字小文字を区別しない）
  • HEIC入力: 一時的に sips で PNG へ変換して補正、出力は PNG（中間PNGは自動削除）
  • PNG/JPG/JPEG入力: 変換なしでそのまま補正、同じ拡張子で出力（拡張子は小文字化）
  • 出力ファイル名: 元ファイル名_corrected.拡張子（例: 1.heic → 1_corrected.png）
  • 依存チェック: 実行時に opencv-python / numpy の有無を確認し、無ければ案内して終了
  • 罫線が検出できない場合: 警告を出し、補正せず元画像をコピー
  • 処理時間: 1枚あたり数秒（角度探索が総当たりのため）
  • 必要ツール: sips（macOS標準）、Python3、opencv-python、numpy

🔬 検出ロジック（投影プロファイル法）

線分を1本ずつ検出して角度を平均するのではなく、画像全体の罫線画素から一括で角度を決めます。

  1. グレースケール化し、adaptiveThreshold（平均法・ブロックサイズ31）で二値化
  2. モルフォロジー演算（オープニング）で罫線のみを抽出
    • 縦罫線: (1, 高さ/60) の縦長カーネル → 横線と文字が消える
    • 横罫線: (幅/60, 1) の横長カーネル → 縦線と文字が消える
  3. 罫線画素について、候補角度ごとに投影プロファイルを作り、集中度（ヒストグラムの二乗和）が最大になる角度を探索する
  4. 探索は2段階（粗探索: ±5度を0.05度刻み → 精密探索: 粗探索値の±0.08度を0.005度刻み）
  5. 回転補正を適用
  6. 回転補正後の画像でせん断角を測り直し、せん断補正を適用
  7. 補正後に再測定し、残存角度を表示

この方式の利点は、個々の線分の端点誤差が平均化され、画像全体の十数万〜二十万画素から1つの角度を決めるため、罫線が途中で分断されていても短くても結果に影響しないことです。

実測値（動作確認済みサンプル6枚）は、検出値 回転 0.005〜0.17度／せん断 0〜0.70度に対し、補正後の残存はすべて 0.05度以内。3500px の画像で端から端まで約3pxのずれに相当し、目視でも解消を確認済みです。検出画素数の目安は横罫線 17万〜22万、縦罫線 3.4万〜4.8万画素です。

#!/usr/bin/env python3
"""
書類画像の傾き補正ツール（投影プロファイル法）

モルフォロジー演算で罫線のみを抽出し、投影プロファイルの分散が
最大になる角度を粗探索→精密探索の2段階で求める。
線分ごとの端点誤差に左右されないため、Hough変換より安定する。
"""

import sys
import math
import cv2
import numpy as np

COARSE_RANGE = 5.0
COARSE_STEP = 0.05
FINE_SPAN = 0.08
FINE_STEP = 0.005
MIN_PIXELS = 2000
MAX_SAMPLES = 400000


def binarize(gray):
    return cv2.adaptiveThreshold(
        gray, 255, cv2.ADAPTIVE_THRESH_MEAN_C,
        cv2.THRESH_BINARY_INV, 31, 15)


def extract_vertical(bw, h):
    ksize = max(15, h // 60)
    kernel = cv2.getStructuringElement(cv2.MORPH_RECT, (1, ksize))
    return cv2.morphologyEx(bw, cv2.MORPH_OPEN, kernel)


def extract_horizontal(bw, w):
    ksize = max(15, w // 60)
    kernel = cv2.getStructuringElement(cv2.MORPH_RECT, (ksize, 1))
    return cv2.morphologyEx(bw, cv2.MORPH_OPEN, kernel)


def _score(a_axis, b_axis, k, nbins, offset):
    proj = a_axis - k * b_axis
    idx = np.clip((proj + offset).astype(np.int32), 0, nbins - 1)
    hist = np.bincount(idx, minlength=nbins).astype(np.float64)
    return float((hist ** 2).sum())


def _search(a_axis, b_axis, lo, hi, step, nbins, offset):
    best_a, best_s = 0.0, -1.0
    a = lo
    while a <= hi + 1e-9:
        s = _score(a_axis, b_axis, math.tan(math.radians(a)), nbins, offset)
        if s > best_s:
            best_s, best_a = s, a
        a += step
    return best_a


def find_angle(mask, vertical):
    pts = np.column_stack(np.nonzero(mask))
    n = len(pts)
    if n < MIN_PIXELS:
        return 0.0, n

    ys = pts[:, 0].astype(np.float64)
    xs = pts[:, 1].astype(np.float64)

    if n > MAX_SAMPLES:
        sel = np.random.default_rng(0).choice(n, MAX_SAMPLES, replace=False)
        ys, xs = ys[sel], xs[sel]

    if vertical:
        a_axis, b_axis = xs, ys
        size, other = mask.shape[1], mask.shape[0]
    else:
        a_axis, b_axis = ys, xs
        size, other = mask.shape[0], mask.shape[1]

    b_axis = b_axis - b_axis.mean()
    margin = int(math.tan(math.radians(COARSE_RANGE)) * other) + 10
    nbins = size + 2 * margin

    coarse = _search(a_axis, b_axis, -COARSE_RANGE, COARSE_RANGE,
                     COARSE_STEP, nbins, margin)
    fine = _search(a_axis, b_axis, coarse - FINE_SPAN, coarse + FINE_SPAN,
                   FINE_STEP, nbins, margin)
    return fine, n


def measure(img):
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    h, w = gray.shape
    bw = binarize(gray)
    rot, hn = find_angle(extract_horizontal(bw, w), vertical=False)
    shear, vn = find_angle(extract_vertical(bw, h), vertical=True)
    return rot, hn, shear, vn


def measure_shear(img):
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    bw = binarize(gray)
    return find_angle(extract_vertical(bw, gray.shape[0]), vertical=True)


def rotate_full(img, angle_deg):
    h, w = img.shape[:2]
    center = (w / 2, h / 2)
    M = cv2.getRotationMatrix2D(center, angle_deg, 1.0)
    cos, sin = abs(M[0, 0]), abs(M[0, 1])
    new_w = int(h * sin + w * cos)
    new_h = int(h * cos + w * sin)
    M[0, 2] += (new_w / 2) - center[0]
    M[1, 2] += (new_h / 2) - center[1]
    return cv2.warpAffine(img, M, (new_w, new_h),
                          flags=cv2.INTER_CUBIC, borderValue=(255, 255, 255))


def shear_fix(img, angle_deg):
    h, w = img.shape[:2]
    k = math.tan(math.radians(angle_deg))
    y_ref = h / 2
    shift_max = abs(k) * (h / 2)
    pad = int(math.ceil(shift_max)) + 5
    new_w = w + 2 * pad
    M = np.array([
        [1, -k, pad + k * y_ref],
        [0, 1, 0]
    ], dtype=np.float64)
    return cv2.warpAffine(img, M, (new_w, h),
                          flags=cv2.INTER_CUBIC, borderValue=(255, 255, 255))


def main():
    if len(sys.argv) != 3:
        print("使い方: python3 deskew.py input.png output.png")
        sys.exit(1)

    in_path, out_path = sys.argv[1], sys.argv[2]
    img = cv2.imread(in_path)
    if img is None:
        print(f"エラー: 画像を読み込めません: {in_path}")
        sys.exit(1)

    rot, hn, shear, vn = measure(img)
    print(f"[{in_path}] 回転角 {rot:+.4f} 度 (横罫線 {hn} 画素) / "
          f"せん断角 {shear:+.4f} 度 (縦罫線 {vn} 画素)")

    if hn < MIN_PIXELS and vn < MIN_PIXELS:
        print(f"[{in_path}] 警告: 罫線を検出できませんでした。補正は行いません。")
        cv2.imwrite(out_path, img)
        sys.exit(0)

    out = img
    if abs(rot) > 0.005:
        out = rotate_full(out, rot)
        shear, vn = measure_shear(out)
        print(f"[{in_path}] 回転補正後のせん断角 {shear:+.4f} 度 "
              f"(縦罫線 {vn} 画素)")
    if abs(shear) > 0.005:
        out = shear_fix(out, shear)

    r2, hn2, s2, vn2 = measure(out)
    print(f"[{in_path}] 補正後の残存: 回転 {r2:+.4f} 度 / せん断 {s2:+.4f} 度")

    cv2.imwrite(out_path, out)
    print(f"[{in_path}] -> [{out_path}] 補正完了\n")

⚠️ 実装時につまずいた点

1. OpenCV のバージョン差で HoughLinesP の返り値の形が変わる

症状: for line in lines: x1, y1, x2, y2 = line[0] と書くと、環境によっては TypeError: cannot unpack non-iterable numpy.int32 object になる。

対処: lines = lines.reshape(-1, 4) で形状を揃えてから for x1, y1, x2, y2 in lines: と回す。

注記: 現行版は HoughLinesP を使わないため発生しないが、同種のツールで再発しやすい。

2. zsh の status は予約変数

症状: ローカル変数名に status を使うと read-only variable: status エラーになる。

原因: status は $? の別名として zsh が予約しているため。

対処: rc などの別名に変える。

注記: bash では予約されていないので、bash由来のコードを持ち込むと出やすい。

3. せん断角は必ず回転補正「後」の画像で測り直す

症状: 補正後の残存せん断角が、検出した回転角とほぼ同じ値になる。

原因: 回転補正前に測ったせん断角を、回転補正後の画像に適用していた。画像を回転させると縦罫線の角度も回転角の分だけずれるため、ずれ量がちょうど回転角に一致する。

対処: 回転補正を適用したあと、せん断角を測り直してから適用する。

注記: 回転がほぼ0のファイルでは症状が出ないため、回転角が有意なファイルを必ずテストに含める。

4. 回転補正の符号

症状: 補正後の残存回転角が、検出値のちょうど2倍になる。

原因: rotate_full(img, -rot) と符号を反転させていた。cv2.getRotationMatrix2D は正の角度で反時計回りに回転させるが、検出側は画像座標系（y軸が下向き）で角度を返すため符号反転は不要。

対処: rotate_full(img, rot) とする。

注記: 「ちょうど2倍」は符号ミスの典型的なサイン。

5. Hough変換の線分ごとの角度平均では精度が出ない（設計上の教訓）

症状: 線は十分な本数検出できているのに、補正しても歪みが半分程度しか減らない。

原因: HoughLinesP は1本の物理的な罫線を複数の短い線分に分断して返す。線分ごとに端点のピクセル誤差で角度が変わり、同じ罫線から 0.417 / 0.782 / 0.561 / 0.908 度といったばらつきが生じる。500px の線分では端点1ピクセルのずれが 0.11度の誤差になる。

対処: 投影プロファイル法に切り替える。

注記: この症状は「台形歪みではないか」と誤診しやすい。実際に垂直線の角度とx座標の相関を測ったところ相関係数は -0.13〜-0.22 と弱く、遠近歪みではなく測定精度の問題だと判明した。原因を推定する前に、角度と位置の相関を測って切り分けるのが確実。

⚠️ 既知の制約

  • 罫線がしっかり入った表形式の書類を前提としたロジックです。罫線が薄い／少ない書類では検出精度が落ちます
  • HEIC は OpenCV で直接読めないため sips での変換工程が必須です（関数内で自動処理）
  • 出力ファイル名は英数字（ASCII）で統一しています
  • 角度探索は総当たりのため、1枚あたり数秒かかります
  • 補正できるのは回転とせん断（アフィン変換の範囲）までです。原稿の浮きや撮影角度による遠近歪み（台形歪み）は補正できません。その場合は射影変換が必要になります

🔍 コマンドの動作説明

カレントディレクトリの全 PDF ファイルに対して、Title をファイル名（拡張子なし）、Author と Creator を「行政書士 伊藤正昭」に一括書き換えます。Pages で書き出した PDF に「名称未設定.pages」「Pages」のまま残るメタ情報を修正するために使用します。

💡 使用方法

  1. 対象の PDF が入ったフォルダへ移動
  2. ターミナルで pmeta を実行
  3. 複数 PDF がある場合は一括処理され、各ファイルに「完了: ファイル名」と表示されます

⚙️ 設定されるメタ情報

  • Title: ファイル名（拡張子なし）
  • Author: 行政書士 伊藤正昭
  • Creator: 行政書士 伊藤正昭
  • 元ファイルを直接上書き（-overwrite_original）

🛠️ 必要環境

  • exiftool（未導入の場合: brew install exiftool）

📋 エイリアスの登録コマンド

cat >> ~/.zshrc << 'EOF'
alias pmeta='for pdf in *.pdf; do [ -f "$pdf" ] || continue; base="${pdf%.pdf}"; exiftool -Title="$base" -Author="行政書士 伊藤正昭" -Creator="行政書士 伊藤正昭" -overwrite_original "$pdf"; echo "完了: $pdf"; done'
EOF
